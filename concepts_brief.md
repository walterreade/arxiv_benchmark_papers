# All-ArXiv AI Benchmark Corpus Expansion & Gemini Decision 1 Architecture

* **Author:** Walter Reade
* **Date:** 2026-11-13

## Overview

This project expands [README.md](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/README.md) from tracking religious-bias papers in Large Language Models (LLMs) to indexing **all Artificial Intelligence (AI) benchmark papers on arXiv** across every modality and domain (language, vision, audio, video, multimodal, agents, robotics, tabular data, and scientific, medical, legal, or industrial AI). Walter Reade will use this corpus to identify gaps in industry benchmarks—spotting capabilities, domains, languages, and failure modes that lack strong evaluation coverage—while keeping the existing religious-bias reports and daily updates running as a specialized downstream module.

To stay focused on benchmark gap discovery rather than general machine learning papers, the benchmark corpus includes only papers whose contribution **introduces, extends, audits/critiques, or surveys** benchmarks, datasets, or evaluation methods. Empirical papers that merely test a model on existing benchmarks are excluded from the benchmark corpus (unless they qualify independently for the downstream religious-bias module).

The redesign also evaluates Google's **Gemini Decision 1** (`gemini-decision-1` via `POST /v1beta/decisions`) alongside **Gemini Flash**, prioritizing **extraction and classification accuracy over minimizing API token spend**, and moves operational state off flat Network File System (NFS) CSV/JSON files into a local SQLite database on Non-Volatile Memory Express (NVMe) storage (`~/`). Across seven review lenses, `gemini-decision-1` provides clear accuracy and calibration benefits when used at **one paper per call** for Stage 1 abstract triage and for on-demand closed-rubric gap sweeps ($0.10 per 1M input tokens, $0 output tokens), while **Gemini Flash** handles single-pass native multimodal PDF extraction via inline PDF bytes—preserving tables, figures, and layouts without keeping terabytes of PDFs on local disk.

### Current Pipeline Bottlenecks & Data Corruption

Auditing the live repository uncovered concrete defects that already cause silent data loss and block scaling from 1,500 religious-bias papers to tens of thousands of AI benchmark papers:

- **Silent CSV Column-Shift Corruption:** [1st_pass_results.csv](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/utility_files/1st_pass_results.csv#L1-L5) has a 12-column header, but [2_extract_paper_metadata.py](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/scripts/2_extract_paper_metadata.py#L335-L389) later appended 16-column rows without updating the header. Starting around row 79,230, `csv.DictReader` shifts boolean tags into `reference_count`, `appendix_length`, and `reasoning`.
- **Over-Broad Legacy Benchmark Flag:** [2_extract_paper_metadata.py](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/scripts/2_extract_paper_metadata.py#L76) asked `"True if and only if the paper deals with benchmarking"`, causing 55,270 of 79,264 downloaded papers to be marked `is_benchmark=True`, including ordinary empirical model papers. Under the stricter contribution rule (introduces, extends, audits, or surveys), true AI benchmark contributions across all of arXiv are estimated at **35,000 to 80,000 papers**, rather than 300,000.
- **Unversioned Cache Poisoning & Array Alignment Bugs:** [1_classify_and_download_arxiv_papers.py](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/scripts/1_classify_and_download_arxiv_papers.py#L400-L407) sends 100 abstracts per prompt and pads `[False]` at the end whenever Gemini returns fewer than 100 booleans, shifting labels across subsequent papers in the batch. Those bare `{arxiv_id: false}` values were saved with no prompt version in [download_assessments_cache.json](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/utility_files/download_assessments_cache.json) across 3,097,115 papers.
- **Truncated Snapshot & Unnoticed Cron Outages:** [arxiv-metadata-oai-snapshot.json](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/utility_files/arxiv-metadata-oai-snapshot.json) ends on `2026-01-05` with a cut-off final JSON line that [1_classify_and_download_arxiv_papers.py](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/scripts/1_classify_and_download_arxiv_papers.py#L87-L89) silently ignores. Daily updates stopped on `2026-10-23` (21 days before `2026-11-13`), exceeding the script's hardcoded 7-day / 4,000-paper Atom API window, while [run_update.sh](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/run_update.sh#L33-L79) logs stage failures as non-fatal warnings into an unrotated 509 MB `cron.log`.
- **Poisoned JSONs & Bug-Induced Blacklists:** When JSON parsing fails three times in Stages 2–4 ([2_extract_paper_metadata.py](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/scripts/2_extract_paper_metadata.py#L107-L110), [3_extract_bias_targets.py](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/scripts/3_extract_bias_targets.py#L106-L109), [4_extract_paper_details.py](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/scripts/4_extract_paper_details.py#L95-L98)), the scripts write `{"raw_response": ...}` to disk and mark the paper complete. Meanwhile, [shared.py](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/scripts/shared.py#L131-L152) permanently skips 548+ papers in `2nd_pass_failures.csv` and `3rd_pass_failures.csv` that failed due to code bugs (`'list' object is not a mapping`, `NoneType`).
- **NFS Locking & Git Bloat:** `/mnt/filestore` is mounted as NFSv3 with `local_lock=none`, where SQLite file locks do not function safely under concurrent writes and flat directory scans of ~79k files take hours. Committing data files via `git add -A` in [run_update.sh](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/run_update.sh#L244) has grown `.git` to 3.7 GB.

### Inventive Contradictions, Resolution Patterns & Ideal Final Result

Resolving the system's core trade-offs under a **quality-first** priority yields four architectural patterns:

1. **Multimodal Table/Figure Extraction Quality vs. Local Disk & Files API Limits:**
   - *Contradiction:* Benchmark papers place critical details (leaderboards, task breakdowns, modality matrices, dataset splits) inside multi-column tables and figures that plain-text parsers like `pypdf` scramble, yet storing 80,000+ PDFs locally consumes hundreds of gigabytes and calling `client.files.upload()` across tens of thousands of PDFs hits polling delays and the 20 GB active Gemini Files API storage cap.
   - *Resolution (Ephemeral Staging + Inline Multimodal PDF Bytes + Evidence Card):* Fetch each qualifying PDF temporarily into memory or a bounded NVMe staging directory (pulling historical PDFs at multi-Gbps from arXiv's Google Cloud bucket `gs://arxiv-dataset/arxiv/` rather than scraping `arxiv.org/pdf/`). Pass the raw PDF bytes **inline** (`types.Part.from_bytes(mime_type="application/pdf")` for PDFs `<20 MB`, which covers ~98% of arXiv papers at 3.8 MB average; falling back to `files.upload()` + immediate `files.delete()` only for `>=20 MB` PDFs) into a **single Gemini Flash call**. Flash reads native tables and figures to extract structured metadata plus a comprehensive **Benchmark Evidence Card**, while local `pymupdf`/`pypdf` text is also saved compressed in SQLite for offline full-text search. Archive the PDF to date-sharded `gs://inversion/pdf/<YYMM>/` and delete the local file immediately.
2. **Structured Coverage Matrices vs. Evolving Gap Questions:**
   - *Contradiction:* Finding gaps requires normalized categorical tables for clean SQL joins, yet new evaluation questions will emerge as Walter explores the corpus.
   - *Resolution (Hybrid Normalized Tables + Declarative Rubric Layer + Entropy Detection):* Combine normalized junction tables for core dimensions (`paper_modalities`, `paper_tasks`, `paper_models`, `paper_benchmarks`) with a versioned `decision_scores(arxiv_id, rubric_id, rubric_version, question_id, choice_or_score, probability)` table powered by `gemini-decision-1` over stored Evidence Cards + extracted text. Adding a new 100-question gap rubric requires only a YAML/JSON definition and a fast `gemini-decision-1` sweep—no `ALTER TABLE` migrations and no PDF re-downloads. Including an `"Other / Emergent"` choice and monitoring high-entropy probability distributions highlights emerging benchmark paradigms automatically.
3. **Maximum Triage Calibration vs. Batching Interference:**
   - *Contradiction:* Stuffing 50–100 abstracts into a single prompt saves requests but introduces cross-abstract attention interference or array-alignment bugs.
   - *Resolution (1-Paper-Per-Call Shared-Input Fanout):* Because quality takes priority over minimizing API spend, Stage 1 calls `POST /v1beta/decisions` (`gemini-decision-1`) with **one paper's title, abstract, and categories per request** and evaluates 4 orthogonal typed questions (`is_benchmark_contribution`, `contribution_type`, `primary_modality`, `is_llm_bias_ethics_religion`) in a single forward pass (~700 input tokens/paper = ~$90 total for 1.3M pre-filtered papers, $0 output tokens), giving isolated, calibrated probabilities (`0.01–0.99`) per paper.
4. **NVMe SQLite Speed vs. Single-Disk Failure & Legacy Script Coupling:**
   - *Contradiction:* Moving SQLite to local NVMe (`~/`) fixes NFS locking bugs and Git bloat, but makes the VM's disk a single point of failure while existing religious-bias scripts include non-benchmark empirical bias studies.
   - *Resolution (Atomic Checkpoints + Orthogonal Routing Track):* Funnel SQLite writes through a single writer queue in Write-Ahead Logging (WAL) mode and run post-pipeline `VACUUM INTO` + `zstd` backups to both `/mnt/filestore/.../backups/` and `gs://inversion/backups/sqlite/`. Scoring `is_llm_bias_ethics_religion` independently in Stage 1 ensures empirical LLM bias papers (such as model evaluations on BBQ) continue flowing into the downstream religious-bias module.

**Ideal Final Result:** Every qualifying arXiv AI benchmark paper is streamed from cloud storage, analyzed once with full multimodal PDF fidelity (tables and figures intact) by Gemini Flash without local PDF hoarding or Files API quota leaks, indexed into normalized SQLite facet tables and FTS5 on local NVMe, and re-scorable across arbitrary new gap rubrics in minutes via `gemini-decision-1`.

### Model Division of Labor: Gemini Decision 1 vs. Gemini Flash

Upgrading `google-genai` from `>=1.60.0` to `>=3.2.0` (and removing the unused `google-generativeai` dependency from [pyproject.toml](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/pyproject.toml#L7-L8)) unlocks `POST /v1beta/decisions` (`gemini-decision-1`: $0.10/1M input tokens, $0 output tokens, zero text output, 262,144-token context limit, up to 1,000 typed questions per call).

| Pipeline Task | Assigned Model / Tool | Input Source | Quality Rationale & Cost Estimate |
| :--- | :--- | :--- | :--- |
| **Stage 0: Archive Pre-Filter** | Local Python filter | Metadata JSONL / Atom delta | Drops ~2.0M–2.2M pure math/physics papers for **$0** while rescuing cross-domain scientific/medical AI benchmarks (`q-bio`, `physics`, `econ`, `stat`) via generous keyword regex so recall is not lost. |
| **Stage 1: Abstract Triage (~1.1M–1.3M papers)** | `gemini-decision-1` (1 paper/call) | Title + Abstract + Categories | Evaluates 4 orthogonal questions per paper with zero cross-abstract interference, zero JSON alignment bugs, and calibrated probabilities (`0.01–0.99`). **~$90 one-time backfill**. |
| **Stage 2: Multimodal Benchmark Extraction (~35k–80k papers)** | `Gemini Flash` (inline PDF bytes, Pydantic `response_schema`) | Ephemeral staged PDF (`Part.from_bytes` for `<20 MB`; Files API fallback for `>=20 MB`) | Reads native tables, figures, and text in **one pass** to extract open-ended strings (`benchmark_names`, `urls`, `tasks`, `models_tested`, `base_benchmarks`, `limitations`, detailed Evidence Card) plus normalized core facets. **~$250–$650 backfill** (50% less via Gemini Batch API). |
| **Citation & Venue Graph** | Semantic Scholar Batch API + local parser | `arxiv_id` batches (500/call) | Fetches canonical `references`, `venue`, and `citationCount` without LLM transcription truncation errors, replacing the $O(N^2)$ fuzzy-matching loop in [generate_full_analysis.py](file:///mnt/filestore/walter/lds_projects/arxiv_benchmark_papers/scripts/generate_full_analysis.py#L392-L465) for **$0**. |
| **Stage 3: Iterative Gap-Rubric Sweeps** | `gemini-decision-1` (1 paper/call, multi-question) | Stored Abstract + Detailed Flash Evidence Card + Section Summaries (~2k–4k tokens) | Evaluates 50–250 closed Yes/No, multiple-choice, or ordinal gap-rubric questions per paper without autoregressive label bias. **~$15–$35 per full-corpus sweep** ($0 output tokens). |

**Operational Guardrails for Model Calls:**
1. **Stage 0 Calibration Benchmark (200–500 Papers):** Before running the 1.3M-paper backfill, evaluate `gemini-decision-1` (1 paper/call) on a stratified 200–500 paper validation set (including hard negatives where empirical papers merely evaluate models on existing benchmarks) to select the probability threshold that maximizes recall and precision and verify `/v1beta/decisions` RPM throughput.
2. **262,144-Token Context Guard:** Enforce automatic token counting and section trimming whenever text passed to `gemini-decision-1` approaches its 262k context ceiling.
3. **Do Not Re-Send Full PDFs to `gemini-decision-1` Alongside Flash:** Because Gemini Flash already reads the full native PDF once in Stage 2 and synthesizes a rich Evidence Card (plus normalized core tags), sending raw PDFs a second time to `gemini-decision-1` adds failure modes (15 MB URI / 262k token limits on appendix-heavy survey PDFs) without improving accuracy over scoring the structured Evidence Card + extracted text.

## Goals vs. Non-Goals

* **In-Scope Goals:**
  - Index all arXiv AI papers (across all modalities and domain verticals) whose contribution introduces, extends, audits/critiques, or surveys benchmarks, datasets, or evaluation methods, catching up across the `2026-01-05` snapshot cutoff and the post-`2026-10-23` pause via `gs://arxiv-dataset` + category-scoped Atom deltas.
  - Migrate structured state off flat NFS CSV/JSON files into a local NVMe SQLite database (`~/`) combining lossless JSON + compressed text, normalized facet junction tables, FTS5 full-text search, pre-joined read views, and automated compressed backups to GCS and Filestore.
  - Use `gemini-decision-1` (`google-genai >= 3.2.0`) at 1 paper per call for high-calibration Stage 1 abstract triage and multi-question on-demand declarative gap-rubric sweeps.
  - Maximize Stage 2 extraction fidelity using single-pass native multimodal PDF inputs (`Part.from_bytes` inline PDF bytes into Gemini Flash) staged ephemerally on NVMe and archived to date-sharded `gs://inversion/pdf/<YYMM>/`, paired with Semantic Scholar batch citation/venue enrichment.
  - Preserve 100% longitudinal parity for existing religious-bias reports, daily updates, talk facts, and `/find-citations` via an orthogonal Stage 1 routing flag (`is_llm_bias_ethics_religion`).
* **Out-of-Scope Non-Goals:**
  - Extracting general AI benchmark profiles for empirical ML papers that merely report model scores on existing benchmarks without introducing, extending, auditing, or surveying an evaluation artifact.
  - Retaining hundreds of gigabytes of permanent raw `.pdf` files on the local VM disk after extraction and GCS archival complete.
  - Indexing non-arXiv closed-access publisher repositories in v1 (beyond citation/venue metadata fetched via Semantic Scholar).
  - Building a hosted multi-user web application before CLI/SQLite gap-analysis workflows stabilize.

## Alternatives Weighed

- **Ingest all empirical AI papers that evaluate models on benchmarks:** Rejected by author. Roughly 80%+ of empirical ML papers run benchmark tests; including them adds 500,000+ model papers that obscure benchmark coverage gaps.
- **Keep flat JSON/CSV state on `/mnt/filestore` or store 1+ TB of permanent PDFs on local `/dev/root`:** Rejected during ideation and design review. `/mnt/filestore` uses NFSv3 with `local_lock=none` (unsafe for SQLite locks and slow on 79k-file directories), while permanent local PDF hoarding fills the OS root partition when ephemeral local staging + `gs://inversion/pdf/<YYMM>/` archival achieves full extraction fidelity with near-zero permanent local PDF footprint.
- **Plain-text-only (`pypdf`) extraction instead of native PDF input for Stage 2 Gemini Flash:** Rejected after author prioritized extraction quality over minimizing token cost. Multi-column benchmark leaderboards, task diagrams, and dataset split tables frequently scramble under `pypdf`; passing raw PDF bytes inline (`Part.from_bytes`) preserves visual table/figure layout while avoiding `client.files.upload()` polling and 20 GB quota leaks.
- **Multi-abstract batching (50–100 abstracts per call) in `gemini-decision-1` Stage 1 triage:** Rejected in favor of 1 paper per call (~$90 total backfill) to eliminate cross-abstract attention interference and maximize per-paper probability calibration.
- **Minimal JSON-only SQLite schema without normalized junction tables:** Rejected in favor of a hybrid schema (lossless `extraction_json` + normalized `paper_modalities`, `paper_tasks`, `paper_models`, `paper_benchmarks` junction tables + `decision_scores` EAV + FTS5) to maximize query reliability and join speed for coverage-matrix analysis.
- **Use `gemini-decision-1` alone without a generative model, or double-send raw PDFs to both `gemini-decision-1` and Flash:** Rejected on technical grounds. `gemini-decision-1` emits zero text tokens (cannot extract names, URLs, or summaries) and enforces stricter PDF size/262k-token ceilings than Flash; running `gemini-decision-1` downstream over Flash's detailed Evidence Card + extracted text achieves higher reliability on long survey/appendix papers.
- **Build a custom OAI-PMH harvester or LLM bibliography transcriber:** Rejected (`egm-design`, `egm-zoom-out`). `gs://arxiv-dataset/metadata-v5/` + category-scoped Atom deltas avoid OAI-PMH `datestamp` amplification, and Semantic Scholar's batch API provides clean citation graphs without LLM truncation errors or $O(N^2)$ string matching.

1. **Author & Quality Mandate:** Authored by Walter Reade; design choices prioritize classification calibration, table/figure extraction accuracy, and gap-query richness over aggressively minimizing token spend.
